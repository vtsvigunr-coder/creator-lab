# Multilingual site (EN default, RU added) — design

## Goal
Add a Russian translation of the entire site and a language switcher in the header menu (desktop and mobile), reachable via separate URLs for SEO.

## Routing & language state
- Add `react-router-dom`.
- Two routes render the same `App` tree:
  - `/` → English (default)
  - `/ru` → Russian
- `src/i18n/LanguageContext.tsx` exports a `LanguageProvider` and `useTranslation()` hook. The provider derives the active language from the matched route (not client state/localStorage — English is always the default entry point, per user decision) and exposes:
  - `t`: the active language's translation dictionary
  - `lang`: `'en' | 'ru'`
  - `switchLanguage(lang)`: navigates between `/` and `/ru` via `useNavigate()`
- The provider sets `document.documentElement.lang` on route change.
- Switching languages is a normal client-side route change. Both routes mount a fresh `App` tree (React Router treats them as different matches), so scroll resets to top and entrance animations replay. This is accepted behavior, not a bug to fix later.

## Translation content
- `src/i18n/translations/en.ts` and `src/i18n/translations/ru.ts`, both implementing a shared `Translations` type (defined in `src/i18n/types.ts`) so a missing key is a type error, not a silent fallback.
- Keyed by section, matching `src/sections/*`: `hero`, `header` (nav sitemap labels, legal labels, "Get Started", "Menu"/"Close" toggle labels), `problem`, `solution`, `howItWorks`, `forBrands`, `forCreators`, `ourPlatform`, `whyNow`, `whyCreatorsJoin`, `faq`, `ctaFooter`.
- Every hardcoded user-visible string in those 11 section components plus `Header.tsx`/`NavMenu.tsx`/`HeroButtons.tsx`/`CircleRevealButton` usages moves into the dictionaries and is read via `t.<section>.<key>`.
- `SOCIAL_ICONS` labels (Instagram/LinkedIn/X/Telegram) stay as-is (accessible alt text only, not visible copy, and are proper nouns).
- Legal Policy pages don't exist yet (nav links are already inert), so only their nav labels are translated, not page content.

## Language switcher UI
- Lives in `NavMenu`'s existing "Social" group (shared markup for desktop and mobile), to the right of the social icons.
- Plain text `EN` / `RU`, same row, small gap. Active language: full opacity / bold. Inactive: dimmed, clickable, same hover treatment as the social icons (opacity 0.92 → 1).
- Clicking the inactive one calls `switchLanguage()` and closes the menu (same as other nav actions).

## Testing
- Existing component tests that assert on hardcoded English strings need updating to import from `en.ts` or to wrap with the provider at `/`.
